## The government-feed run (25–26 Sep)

```bash
SANDBOX_EMAIL=... SANDBOX_PASSWORD=... uv run --no-sync python scripts/onboard_sandbox.py   # 30 cameras by RTSP
uv run --no-sync python scripts/rotate_worker.py --minutes 12 --cycles 2 --group CAM17,CAM18,CAM12,CAM14 ...
uv run --no-sync python bench/sandbox_summary.py      # bench/results/sandbox.md
uv run --no-sync python bench/sandbox_plates.py       # bench/results/sandbox_plates.md
uv run --no-sync python bench/sandbox_eye.py sheets   # then label, then: ... sandbox_eye.py score
uv run --no-sync python bench/sandbox_daynight.py     # bench/results/sandbox_daynight.md: the 25 Sep evening and 26 Sep morning runs (blind table by run, then the AI one)
uv run --no-sync python bench/sandbox_eye.py score --from-db   # reviews people made on the Plate review page (blind and verify apart)
uv run --no-sync python scripts/detection_report.py --prefix gov_detections --camera CAM01 ... --since ... --until ...
(cd submission/build && CAMS=CAM04,CAM02,CAM06,CAM05 node wall_probe.mjs)   # which cameras show a picture on the wall, and how soon
(cd submission/build && PLATE=<a plate read on the sandbox> REPORT=<gov report .html> node record_gov.mjs)
(cd submission/build && node recard_gov.mjs)          # swap only the end card, re-encoded from the kept frames
```

`rotate_worker.py` analysed the sandbox in groups of cameras, a few minutes each, because one laptop decodes only a
handful of streams at full rate; since 7 Oct it starts the worker as `python -m sentinel_analytics.worker` (no .exe
launcher for the antivirus to hold). At the finale nothing rotates: the plate worker keeps a fixed group and the
counts-only worker takes every other camera at once (see "Since the submission" below).

The report `gov_detections_20260925_235916.*` and `Sentinel-Gov-Demo.mp4` are the government-feed deliverables;
both cover the 25 Sep evening run and were made from it before any review. On 26 Sep a team member checked the
stored plates blind on the Plate review page (`/review`): of 120 real Gujarat plates, 90 were stored exactly right
(75.0%) and 107 within one character (89.2%), almost all on the 2 of 30 sandbox views where plates are readable; 54 of 75 in the
25 Sep evening run, 36 of 45 in the 26 Sep morning run (8 cameras) (`bench/results/sandbox_review.md`, `sandbox_daynight.md`).
The sandbox replays fixed clips, each camera's from one time of day and looping, so the two runs replayed the same
footage: they are not a day and night comparison.
An earlier check by our AI assistant with the stored read in view (not blind) gave 92 of 107 (`sandbox_eye.md`); the
blind check showed it was optimistic, so it is quoted only as that. The method was tested on our own cameras, where
the plates are known: the reviewer was right 222 times in 226 (`bench/results/review_truth.md`). The sandbox's
catalogue gives ids and names only: positions and departments are ours (`data/gov-sandbox/locations.json`,
gitignored with the credentials-free onboarding inputs). `record_gov.mjs` writes its own frames
(`gov_frames/`), so it never touches the own-feed video. Its end card gives the evening run's blind figure (54 of 75,
`blind.evening` in `bench/results/sandbox_daynight.json`, since `sandbox_review.json` pools both runs) and says who
checked it (a team member, blind); without blind reviews it falls back to the AI assistant's evening-run figure and
says so. The card's text names no time of day, so the 26 Sep correction needed no new card. `node recard_gov.mjs` swaps only that end card and re-encodes from the kept `gov_frames/` and
`gov.ffconcat` without re-recording, like `retitle.mjs` for the own-feed video; it overwrites
`Sentinel-Gov-Demo.mp4`, so back it up first. Never re-record just to change the card.

Since 26 Sep the worker also drops a read as not a plate when two or more of its letters had to be made from digits
to fit a plate layout (`MAX_LETTERS_FROM_DIGITS`, default 1): the hoarding's phone number on CAM05, stored 24 times on the
sandbox, would not have been stored, and no real sandbox plate would have been lost
(`bench/results/plate_gate_confirm.md`). The government-feed video and report were made before the rule: the report's
100 sightings still include the hoarding's 24 (graded not a plate, so not counted in the 54 of 75), and
`README-for-reviewers.txt` says so.

Plate-reading quality by camera (26 Sep, after the government-feed video and report): the Health page grades every
stored capture and tiers each camera; on the sandbox CAM06 and CAM07 are tier B and the rest C
(`bench/results/capture_quality.md`). The grade does not predict a right read on the blind-checked plates, and the
documents say so.

## Since the submission (26 Sep → 8 Oct)

What changed between the pack and the finale, each measured or in the code; the pack's own files are untouched
(`README-for-reviewers.txt` describes what was submitted), and a one-page addendum for the jury pack says the same.

- **Two profiles instead of rotation.** The plate worker, unchanged, runs on the few cameras whose plates are readable
  (4 streams at about 4.5 analysed fps with object detection, or 8 at 2.9 without: `bench/results/decode.md`). A new
  counts-only worker (`python -m sentinel_analytics.counts`; `services/analytics/sentinel_analytics/counts.py`) runs
  beside it on every other analytics camera at once: vehicle and person counts and intrusion zones from keyframes
  only, decoded by FFmpeg through PyAV (`skip_frame`); a camera whose keyframes are more than 4 s apart is decoded in
  full, and each count row carries `detail.profile` (`keyframes` or `every-frame`). `COUNTS_EXCLUDE` names the plate
  workers' cameras so no zone alerts twice. Measured on one laptop, no plate worker running, the relay's CPU excluded:
  40 streams at 0.78 frame/s per stream on 2.46 CPU cores and 13% GPU, 50 saturate (`bench/results/counts_capacity.md`);
  7 sandbox cameras at 14–34 frames per minute each while the sandbox dropped every session about every 45 s
  (`counts_sandbox.md`). This is the Plan for Scale's tier B keyframe profile, which the pack called "sized but not
  yet built"; its 250-streams-per-node figure stays an assumption. Not measured: both workers on one machine together,
  and count accuracy (per-frame COCO detections, no auto-rickshaw class, night misses).
- **Two laptops.** `RELAY_HOST` lets a worker on another machine reach the relay (the registry stores
  `rtsp://localhost:8554/<code>`); the API's `CORS_ORIGIN_REGEX` and the relay's `WEBRTC_HOST` let the control room
  open from another machine; `.env.b.example` is laptop B's settings file. The topology, the failover drill and the
  judges' hands-on station are in `docs/demo-runbook.md`.
- **New scripts**, one line each. `scripts/lan.ps1`: writes A's LAN address into `.env` (`WEBRTC_HOST`,
  `CORS_ORIGIN_REGEX`) and restarts the relay and API. `scripts/db_backup.ps1 -Dest <USB stick> -Loop 600`: pg_dump
  plus the crops every 10 minutes, the last 12 dumps kept. `scripts/db_restore.ps1 -Source <USB stick>`: B takes over
  from the latest dump; the relay rebuilds every camera path within about 20 s. `scripts/set_passwords.py`: the five
  seeded users' password, from `NEW_PASSWORD` in the environment. `scripts/rotate_secrets.py`: replaces the JWT
  secret, ingest key, publisher credential and database password with random ones, in `.env` and the live database.
  `scripts/set_analytics.py --prefix CAM --on`: analytics on for every camera with that prefix, before the workers
  start. `scripts/onboard_urls.py feeds.csv`: onboards a CSV of stream addresses through the probe → relay → register
  path, so credentials never reach the registry (never the Registry page's bulk CSV for credentialed addresses).
  `bench/g3_check.py` and `bench/g3_wiring.py`: the G3 gate's live checks and wiring pair. `bench/counts_capacity.py`
  and `bench/counts_sandbox.py`: the counts worker's capacity and its sandbox run. `bench/plate_gate_live.py`: reads
  dropped as not a plate in a worker log, counts only. `bench/sandbox_loop.py`: whether the sandbox footage repeats
  (it does; no loop length is established).
- **G3 confidence marking, adopted 8 Oct** (`bench/results/g3_wiring.md`, gate PASS; API setting
  `CONFIDENCE_MARKING`, `false` restores the 26 Sep behaviour): a stored read below 0.9, or an alert on a
  one-character match, is marked "check the crop" in alerts, search, the journey view and the live toast; nothing is
  suppressed and no alert rule changes. The fine-tuned reader ft1 is not adopted (`ocr_ft1.md`: non-inferior, no
  gain on real plates); G0, G2, G2b, G4, G5, G6 are not built; the YOLOX detectors are not trained
  (`pipeline_gates_results.md`). Every accuracy, capture and latency figure in the pack still describes the plate
  pipeline that runs at the finale.
- **Security hardening, 8 Oct.** The laptop ran on the repo's example secrets; anyone on the LAN who had read the
  public repo could sign in as admin, fabricate sightings with the ingest key, or publish over a camera. The secrets
  are rotated by script, the API warns loudly at start while any is still an example value, and two new security
  checks fail on any machine still on the example values (this laptop's were rotated 8 Oct). Also: the simulator's control port (8010; its outage switch has
  no auth) bound to 127.0.0.1; relay paths cannot be taken over by a second publisher (`overridePublisher: no`); the
  onboarding card hides the stream URL while a screen is projected; the ingest key compared in constant time; a
  per-address sign-in rate limit, argon2 off the event loop; `event_ts` timezone-aware and within 14 days, batches
  capped at 5,000 rows; camera codes and stream addresses validated on every registry write path; `rtsp_url` masked in
  `GET /cameras` and the CSV export; `watchlist.check`, `sightings.recent` and the registry export audited;
  district-only users no longer statewide; the API's access log (plate searches, tokens in URLs) off; plate text masked
  in the workers' logs; one spool directory per worker; a SHA-256 per evidence crop in `detection_report.py` (an
  integrity check, not a signature).
- **Stack.** PyAV (BSD-3; its wheels bundle a GPL build of FFmpeg, used for decoding only) joins the licence table in
  the HLD, beside the AGPL-3.0 detectors (whose permissive replacement is planned for the pilot and not trained) and
  react-leaflet.
- **Counts.** `pytest` collects 379 unit tests (57 for the registry's maintenance fields, CSV coercion, alert tags and
  literal search text, 8 for the request guards, 2 for the health monitor's one probe per host, 3 for changing a saved
  review, 8 for the counts worker, 7 for the marking, 13 for registry
  validation, 5 for the ingest schema, 5 for `RELAY_HOST` and the 127.0.0.1 rewrite, 2 for log masking, 1 for the
  login throttle, 13 for evidence crop paths, 8 for the event WebSocket's auth and scope, among the additions); `security_checks.py` makes 23 checks on a machine with a LAN address (the two secrets checks fail on any
  machine still on the example values); smoke stays at 34. All three passed on 8 Oct on the rotated secrets. On 9 Oct `scripts/edge_checks.py`
  makes 189 edge-case checks and `scripts/ui_checks.mjs` 111 control-room checks, live events on a real broker included.

## Detection report

The shipped own-feed report covers 24 Sep 01:30:10–01:39:17 IST on four cameras: the same worker run as
`bench/results/anpr_eval_current.md`, starting just after the test sightings the security checks wrote at
01:29 and 01:30. It holds 10 watchlist alerts and 4 intrusion alerts.

```bash
uv run --no-sync python scripts/detection_report.py --since 2026-09-24T01:30:10 --until 2026-09-24T01:39:17 \
  --camera AMD-TRAF-001 --camera AMD-TRAF-002 --camera AMD-AMC-001 --camera AMD-POL-001 \
  --title "Own-feed demonstration: detected vehicles and number plates" \
  --note "Feeds of our choice, no government feed: two Pexels stock traffic clips (filmed on a Mumbai road) with every plate replaced by a synthetic Gujarat registration (AMD-TRAF-001, AMD-TRAF-002), and two simulator clips with drawn vehicles and synthetic plates (AMD-AMC-001, AMD-POL-001), replayed as RTSP cameras." \
  --note "One analytics worker on these four cameras on a GTX 1650 Ti laptop, 24 Sep 2026; the stored plate is the per-character vote across a vehicle's reads. The same run as the accuracy figures in bench/results/anpr_eval_current.md." \
  --note "Watchlist: mock VAHAN and eGujCop records (local sample data, not the live systems) and one manual entry, GJ13LU9863, a synthetic plate in the AMD-TRAF-002 clip. Intrusion: a demo zone on a kerb strip of AMD-TRAF-001 standing in for a restricted area; the clip loops every 60 s, so the same people re-enter the zone each loop, and the 120 s repeat window lets an alert through every second or third loop."
```

Times without an offset are IST. The front page has one row per distinct plate (first and last
seen, cameras in time order, reads, vehicle type and colour, watchlist status, best crop), with
plates one character apart grouped as "possible same vehicle" but never merged; then a per-camera
table, the vehicle/person counts and the intrusion alerts (zone, what was inside and how many, dwell:
never an image). The appendix lists every read with its crop
(`--no-read-crops` keeps only each plate's best crop). `--note` is repeatable and prints under the
title; use it for the run's conditions. A plain `demo_prep.py` deletes the sightings a report needs.

## Recording the demo video

The recorder drives the real control room in headless Chrome — real clicks, real API calls, live
alerts from the analytics worker — and captures frames over the DevTools screencast. FFmpeg
(inside the simulator's Docker image) assembles them.

```bash
docker compose up -d && powershell -File scripts/api.ps1 && (cd web && npm run dev)
# 1. build history on all six demo cameras for ~10 minutes, then stop the worker
CAMERAS=AMD-POL-001,AMD-AMC-001,GNR-GSRTC-001,MHS-POL-001,AMD-TRAF-001,AMD-TRAF-002 uv run --no-sync sentinel-worker
# 2. clear alerts and deactivate the watchlist, keeping sightings and counts (scene 6 shows them)
uv run --no-sync python scripts/demo_prep.py --keep-sightings
# 3. record with a lighter four-camera worker running, or the video overruns 3 minutes
CAMERAS=AMD-POL-001,AMD-AMC-001,GNR-GSRTC-001,MHS-POL-001 uv run --no-sync sentinel-worker
(cd submission/build && node record.mjs)
```

A plain `demo_prep.py` deletes sightings and counts, and scene 6 (vehicle and person detection) is
then recorded empty without an error. Check the length from the recorder's `captured N frames over
X s` line: the chapters file lists only chapter starts, and the end card runs about 6 s past the last
one. The shipped video is 2:08. It is gitignored, so it is not on GitHub either and this laptop holds the
only copy: back it up before re-recording.

The shipped video's scenes were captured on 23 Sep. They do not show what was added on 24 Sep
(store-and-forward, intrusion zones, the journey view, alert priority and chime), so no document
should describe those as shown in the video; the 24 Sep screenshots show them. On 24 Sep only the
title card was replaced, by `node retitle.mjs`, which re-encodes the kept frames (`out/video_frames/`
and `out/frames.ffconcat`) at the same length. It overwrites `Sentinel-Demo.mp4`: back it up first.

`AMD-TRAF-001` and `AMD-TRAF-002` replay stock traffic footage (Pexels, free to use and modify;
filmed on a Mumbai road, whose signs are visible, so the Ahmedabad names and positions are simulated)
with every plate replaced by a synthetic registration: `feedsim/realclip.py` builds them and
writes the ground truth to `feedsim/media/<CODE>.plates.json`. To add more, give a camera in
`feedsim/cameras.yaml` a `real:` source and run `uv run --no-sync python feedsim/realclip.py <CODE>`;
the publisher starts streaming it once the clip exists.
